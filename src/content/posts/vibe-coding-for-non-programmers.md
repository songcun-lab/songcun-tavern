先交代背景：我不是程序员。大学学矿山机电，博士读管理学，职业生涯全部在能源行业。半年前，我连 Git 是什么都说不清楚。

现在，我在 GitHub 上维护着一个组织（[Songcun Lab](https://github.com/songcun-lab)），十几个仓库，给自己的创业公司做了官网，搭了自己的 Prompt 库和 Agent 实验环境。

这中间发生了什么？我想把这条路完整地记下来，给和我一样的非科班中年人看。

## 第一步：先当用户，别当学生

我见过太多人学 AI 编程，第一步就去买 Python 课。我的建议恰恰相反：先别学编程，先学会用 AI。

我的前一年基本都在「聊天」：用 ChatGPT 写材料，用 Claude 改报告，用 Kimi 查资料。这个阶段看起来和编程毫无关系，但它建立了两个关键能力：一是把需求说清楚的能力，二是判断 AI 输出好坏的能力。

后来我才明白，这两个能力就是 AI 编程的全部核心。代码本身，AI 会写。

## 第二步：遇到 Claude Code，世界变了

真正的转折是 Claude Code。

它和网页聊天最大的区别是：它在你的电脑上干活。你说「帮我做一个网站」，它真的会创建文件、写代码、运行、报错、自己修，直到跑通。你不需要看懂每一行代码，你需要做的是：说清楚要什么，看结果对不对。

第一次用它做出一个能在浏览器里打开的页面时，我盯着屏幕看了很久。那种感觉，和我当年第一次看到自己参与核准的煤矿出煤，有点像——你说出了一个意图，世界因此多了一个东西。

圈子里管这个叫「氛围编程」（Vibe Coding）。我觉得对我们这种人，更准确的说法是：**用管理者的方式编程**。提需求、定标准、做验收——这不就是我们干了二十年的事吗？

## 第三步：环境这一关，咬牙过

说点实在的坑。

非科班的人学 AI 编程，真正劝退的不是代码，是环境：终端、WSL、Git、Node、Python 版本……每一个词都很陌生。我在 WSL 上折腾了整整一个周末，中间想放弃三次。

我的解法很笨但有效：把 AI 当成随身的运维工程师。每一步报错，原样贴给它，让它告诉我下一步敲什么。不理解没关系，先跑通，理解会随着使用慢慢长出来。

环境这一关大概需要两三个不被打扰的晚上。过了这一关，后面全是平地。

## 第四步：让成果留下来

我做的最正确的一件事，是很早就注册了 GitHub，并且强迫自己把所有东西都放上去。

学习笔记放上去（notes-ai-journey），好用的提示词放上去（codex-notes），做的小实验放上去（agent-skills）。GitHub 对我不是代码托管，是学习的存档。绿格子每亮一天，就是给自己的一个交代。

回头看，这形成了一个飞轮：学了就做，做了就存，存了就有轨迹，有轨迹就有信心继续学。

## 给同路人的三句话

如果你也是非科班、也过了四十岁、也想走这条路，我只说三句：

第一，你的行业经验不是包袱，是你最大的本钱。AI 会写代码，但它不知道煤矿的皮带机为什么老出事，你知道。

第二，从一个真实的、你自己需要的小东西开始，不要从教程开始。我做的第一个东西是给自己公司做的官网，因为真的需要，所以做完了。

第三，慢一点没关系。我们不和二十多岁的人比速度，我们比的是：谁能把 AI 和二十年的行业认知焊在一起。这件事，年轻人反而干不了。

酒馆里这杯，敬所有半路出家的人。
