用了两年多 AI，我最近有一个越来越强烈的判断：

**会用 AI 工具的人很快会到处都是，但拥有自己 AI 系统的人，会长期稀缺。**

这篇讲讲我为什么开始搭建自己的「个人 AI 基础设施」（Personal AI Infrastructure，PAI），以及我具体在做什么。

## 零散用工具的天花板

先说问题。

我曾经是典型的「工具收集型」用户：ChatGPT、Claude、Kimi、Manus、Lovart……每个都用，每个都会。但用久了发现三个瓶颈。

第一，**重复劳动**。每次做同类任务，都要重新把背景、要求、格式讲一遍。我给 AI 讲「我是谁、我要什么风格」的次数，可能有几百次。

第二，**成果不沉淀**。对话里产生过很多好东西——好的提示词、好的分析框架、好的文字。但它们散落在几十个对话窗口里，用完即弃，下次从零开始。

第三，**能力不可复制**。我摸索出的工作方法，只存在我的手感里。换一个工具、换一个场景，一切重来。

说到底：我在使用 AI，但我没有积累 AI。每天都在消费能力，没有在建设能力。

## 换一个思路：把自己当成一家公司

转变来自一个类比。

一家公司要用好信息化，靠的从来不是买软件，而是建设自己的基础设施：数据库、流程、制度、知识管理。个人用 AI，道理完全一样。

于是我开始把散落的东西系统化，大致分四层。

**知识层：Obsidian 第二大脑。** 所有资料按「资料原文—加工输出—沉淀知识」三段式组织。AI 帮我处理信息，但处理结果必须落库，不能留在对话里。

**资产层：GitHub 上的 Prompt 库和 Skill 库。** 反复用得顺手的提示词，整理成 [codex-notes](https://github.com/songcun-lab/codex-notes)；可复用的能力封装，放进 agent-skills。遇到同类任务，直接取用，不再即兴发挥。

**执行层：Claude Code + Codex + Manus 的分工。** 深度写作和代码给 Claude Code，快速脚本给 Codex，复杂的多步骤任务（研究、网站、报告）给 Manus。每个工具有明确的岗位职责，像一个小团队。

**接口层：Skill 和 MCP。** 这是我最近研究的重点——把「我的知识 + 我的方法」封装成 AI 可以直接调用的单元。这一步做好了，我的经验才真正变成了系统的一部分，而不是每次都靠嘴讲。

## 一个非科班的人做这件事，现实吗

有人会说：这是工程师才玩得动的东西。

我的体会恰好相反。搭 PAI 最难的部分不是技术——技术上，Claude Code 可以替你完成八成——最难的是**想清楚自己的工作到底由哪些环节组成，哪些可以标准化**。

这是业务能力，不是编程能力。一个管过企业的人，给自己的工作流画泳道图，比写代码熟练多了。

我从今年年初开始做这件事，进度不快：研读了 Claude Code 的运行机制，跑通了几个轻量 Agent 框架，Obsidian 库初具规模，Prompt 库每周都在长。所有过程都公开在 [Songcun Lab](https://github.com/songcun-lab)。

## 为什么值得

最后说说我为什么认定这件事值得做。

AI 模型会越来越强，工具会不断更替——今天的明星产品，两年后可能就没了。但有三样东西是你的，跟着你走：**你的知识库、你的工作流、你封装好的方法**。

模型是租来的，基础设施是自己的。

这就是我理解的「个人 AI 基础设施」：不追新工具，而是让每一次使用 AI 都变成一次建设。慢，但每一步都算数。

和我这个人一样。
